**# Monitoring AWS Direct Connect & Transit Gateway with CloudFormation**

## **Overview**
This document explains the automated deployment of CloudWatch alarms for AWS Direct Connect (DX) and Transit Gateway (TGW) using AWS CloudFormation. It also describes the alerting mechanism through SNS, which notifies Slack and Email when alarms are triggered. The deployment process is automated via GitHub Actions.

## **Key Components & Their Roles**
### **GitHub Actions (CI/CD Automation)**
- Automates the deployment of CloudFormation stacks.
- Ensures that infrastructure changes are applied consistently.
- Triggers CloudFormation updates when new configurations or thresholds are set.

### **CloudFormation (Infrastructure as Code - IaC)**
- Defines and provisions AWS resources in a repeatable and scalable manner.
- Deploys CloudWatch alarms to monitor DX and TGW metrics.
- Creates an SNS topic and subscriptions for notifications.

### **CloudWatch Metrics & Alarms**
- Monitors AWS Direct Connect and Transit Gateway health/performance.
- Triggers alarms when predefined thresholds are breached.
- Sends alarm state changes to SNS.

### **SNS (Notification Hub)**
- Acts as a central hub for receiving CloudWatch alarm events.
- Forwards alerts to subscribed endpoints (Slack and Email).

### **Slack & Email (Alert Endpoints)**
- Receives SNS notifications when alarms are triggered.
- Helps teams respond quickly to network performance issues.

## **Workflow Explanation**
1. **GitHub Actions** deploys the CloudFormation stack.
2. **CloudFormation** provisions CloudWatch alarms to monitor DX and TGW metrics.
3. **CloudWatch** tracks these metrics and detects any threshold violations.
4. When an alarm is triggered, it sends an event to **SNS**.
5. **SNS** distributes the alert to Slack and Email via its subscribed endpoints.

## **Alarm Configuration Details**
- **Direct Connect Metrics Monitored:**
  - Connection state
  - Data transfer rates
  - Errors

- **Transit Gateway Metrics Monitored:**
  - VPN tunnel status
  - Packet loss
  - Latency

## **Alerting Mechanism**
- **Slack Notifications:** Sent in a structured format with severity level and incident details.
- **Email Alerts:** Provide a detailed breakdown of the issue, recommended actions, and links to logs.

## **Managing Subscriptions**
- New endpoints (Slack channels, email addresses) can be added by subscribing to the SNS topic.
- Subscription changes can be managed via AWS Console or CLI.

## **Next Steps & Maintenance**
- Adjust CloudWatch alarm thresholds as needed based on network performance.
- Regularly review SNS subscriptions to ensure alerts reach the right teams.
- Monitor GitHub Actions for deployment failures and troubleshoot accordingly.
